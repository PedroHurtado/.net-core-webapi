OpenAPI Spec

Contrato de API

 
🎯 ROL: Experto en diseño de APIs RESTful y OpenAPI 3.0.

📂 CONTEXTO:
@domain-specification-[Entidad].md
  → Event Storming: todos los 🔵(Comandos)
  → Read Models: todas las 📊 vistas

🎯 TAREA:
Genera especificación OpenAPI 3.0 para [Entidad].

📦 ARCHIVO: docs/openapi/[entidad].yaml

ESTRUCTURA:
- Un endpoint por cada 🔵(Comando) del Event Storming
- Un endpoint GET por cada 📊 Read Model
- Schemas para Request/Response de cada operación
- Enums según domain-spec

RESPONSES:
- 200/201/204 según operación
- 400 Bad Request (formato inválido)
- 404 Not Found (entidad no existe)
- 422 Unprocessable Entity (validación de negocio)
- Todos con ProblemDetails (RFC 7807)

⚠️ RESTRICCIONES:
- ✅ Nombres de endpoints en kebab-case
- ✅ Verbos HTTP semánticos (POST crear, PUT reemplazar, PATCH parcial, DELETE eliminar)
- ✅ Schemas reutilizables en components
- ✅ Descripciones claras en español

Wireframe HTML

Formulario funcional interactivo

 
🎯 ROL: Diseñador UI/UX experto en formularios accesibles y usables.

📂 CONTEXTO:
@domain-specification-[Entidad].md
  → Estado y Estructura (campos del formulario)
  → Invariantes (validaciones)

🎯 TAREA:
Genera wireframe HTML funcional para [Operacion] de [Entidad].

📦 ARCHIVO: wireframes/[entidad]-[operacion].html

SECCIONES:
Agrupa campos lógicamente según domain-spec.
Incluye campos condicionales si los hay.

REQUISITOS:
- Labels asociados a inputs (for/id)
- Validación HTML5 (required, min, max, maxlength, pattern)
- Estados: default, loading, success, error
- Feedback visual en tiempo real
- Tailwind CSS
- JavaScript vanilla (sin frameworks)
- Accesible (ARIA donde necesario)
- Responsive (mobile-first)

INTERACCIONES:
- Mostrar/ocultar campos condicionales
- Preview en tiempo real si aplica
- Validación inline antes de submit

⚠️ RESTRICCIONES:
- ❌ NO frameworks JS (React, Vue, etc.)
- ❌ NO librerías externas excepto Tailwind
- ✅ Funcional standalone (abrir en navegador)
- ✅ Datos de ejemplo pre-cargados
3

Web Components

Componentes nativos reutilizables

 
🎯 ROL: Experto en Web Components nativos y Design Systems.

📂 CONTEXTO:
@wireframes/[entidad]-[operacion].html (wireframe existente)

🎯 TAREA:
Extrae Web Components nativos del wireframe para [Entidad].

📦 ARCHIVO: components/[prefijo]-[componente].js

COMPONENTES A EXTRAER:
Identifica patrones repetidos en el wireframe:
- Campos de formulario (text, number, date, etc.)
- Grupos de selección (radio, checkbox)
- Toggles y switches
- Componentes compuestos específicos del dominio

ESTRUCTURA POR COMPONENTE:
- Shadow DOM encapsulado
- Atributos: name, label, value, required, disabled, error, hint
- Propiedades reflejadas
- Eventos: change, input, invalid
- CSS variables para theming
- Slots para contenido personalizado

API EJEMPLO:
<[prefijo]-text-field
  name="nombre"
  label="Nombre"
  required
  maxlength="100"
  error="El nombre es requerido"
></[prefijo]-text-field>

⚠️ RESTRICCIONES:
- ❌ NO dependencias externas
- ✅ Custom Elements v1
- ✅ Funciona sin build step
- ✅ Accesible (ARIA, focus management)
- ✅ Themeable via CSS custom properties

Storybook Stories

Documentación visual de componentes

 
🎯 ROL: Experto en Storybook y documentación de componentes.

📂 CONTEXTO:
@components/[prefijo]-[componente].js (Web Component existente)
@domain-specification-[Entidad].md (Example Mapping para estados)

🎯 TAREA:
Genera stories de Storybook para [NombreComponente].

📦 ARCHIVO: stories/[NombreComponente].stories.js

STORIES A CREAR:
- Default: estado inicial vacío
- Filled: con datos de ejemplo

- Disabled: deshabilitado

- Estados específicos según Example Mapping del domain-spec

ESTRUCTURA:
export default {
  title: '[Categoria]/[NombreComponente]',
  component: '[prefijo]-[componente]',
  argTypes: { /* controles */ }
};

const Template = (args) => { /* render */ };

export const Default = Template.bind({});
Default.args = { /* props */ };

DOCUMENTACIÓN:
- Descripción del componente
- Tabla de props/atributos
- Ejemplos de uso
- Notas de accesibilidad

⚠️ RESTRICCIONES:
- ✅ CSF 3.0 format
- ✅ Args para cada variante
- ✅ Controls interactivos
- ✅ Docs page auto-generada

Command Slice

Endpoint + Service + Repository + Domain Partial

 
🎯 ROL: Arquitecto experto en Vertical Slice Architecture y CQRS.

📂 CONTEXTO:
@domain-specification-[Entidad].md
  → Event Storming: [Flujo]
  → Example Mapping: [Story]
@[Entidad].cs
@style_guide_examples.md

🎯 TAREA:
Genera slice completo para 🔵([NombreComando]).

📦 ARCHIVO: features/[entidad]/commands/[NombreSlice].cs

ESTRUCTURA (dos namespaces en un archivo):

NAMESPACE 1: Fudie.Features.[Entidad].Commands
- public class [NombreSlice] : IFeatureModule
  - Records: Request, Response (y anidados si necesario)
  - AddRoutes(): [HttpVerb] [Endpoint] → [StatusCode]
  - [Injectable] class Service : IService
  - [Injectable] class Repository : I[Add|Update|Remove]<[Entidad]>

NAMESPACE 2: Fudie.Domain.[Entidad]
- public partial class [Entidad]
  - Método(s) del comando según Event Storming
  - Retorna Result o Result<T>
  - Valida invariantes del Example Mapping

⚠️ RESTRICCIONES:
- ❌ NO try-catch (GlobalExceptionHandler lo maneja)
- ❌ NO lógica de negocio en Service (solo orquestación)
- ✅ Toda lógica de negocio en el método del dominio
- ✅ .ValueOrThrow() / .SuccessOrThrow() para Result
- ✅ Tests vendrán del Example Mapping (TDD)

Query Slice

Endpoint + Service + Repository (solo lectura)

 
🎯 ROL: Arquitecto experto en Vertical Slice Architecture y CQRS.

📂 CONTEXTO:
@domain-specification-[Entidad].md (Read Models 📊)
@[Entidad].cs
@style_guide_examples.md

🎯 TAREA:
Genera query slice para [NombreQuery].

📦 ARCHIVO: features/[entidad]/queries/[NombreQuery].cs

ESTRUCTURA:

NAMESPACE: Fudie.Features.[Entidad].Queries
- public class [NombreQuery] : IFeatureModule
  - Records: Query (params), Response
  - AddRoutes(): GET [Endpoint] → 200
  - [Injectable] class Service : IService
  - [Injectable] class Repository : IGet<[Entidad], Guid>

TIPO: [GetOne | GetList]

Si GetList:
- Query params: filtros, page=1, size=25
- IQuery.Query<[Entidad]>()
- Filtros, OrderBy, Skip/Take, Select

Si GetOne:
- IGetOrThrowAsync con tracking: false
- Include relaciones necesarias

⚠️ RESTRICCIONES:
- ❌ NO partial class (queries no modifican dominio)
- ❌ NO tracking en lecturas
- ✅ Proyección a Response (no exponer entidad)
